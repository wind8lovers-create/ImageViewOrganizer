# Image View Organizer

これまでのプランニング(要件定義)に基づいた、新規Androidプロジェクトです。
`image_sort_selector` からはロジック(知覚ハッシュ・グルーピング)のみを再実装し、UIはすべて新規に組み直しています。

## 開くには

1. Android Studio(Koala以降推奨)で「Open」→ このフォルダ(`ImageViewOrganizer`)を選択
2. 初回オープン時、Gradle Wrapperのjarが同梱されていないため、Android Studioが
   「Gradle wrapper が見つかりません、再生成しますか」といった案内を出すことがあります。
   その場合はそのまま「OK」で進めてください(distributionUrlは Gradle 8.7 を指定済みです)。
3. Sync後、実機(Android 12以降/Pixel 9など)を接続してRun

## 実機フィードバックを受けての修正(2回目)

- **デフォルト読込フォルダを変更**: `Documents`はAndroidのSAF/プライバシー制限で直接アクセスできない
  端末があるため、`Pictures/未整理` に変更しました。
- **段階読込(ストリーミング)**: 2500枚のような大量フォルダでも、まずタイムスタンプ新しい順に
  50枚ずつ画面へ反映し、残りはバックグラウンドで読み込み続けます。全件揃うまで待つ必要はありません。
- **EXIF読込の遅延化**: 撮影日(EXIF)の読込は、実際に「撮影日でソート」を選んだ時だけ行うようにしました。
  以前は全件の初期読込時にEXIFを読みに行っており、これが大量枚数での遅さの主因の一つでした。
- **画面消灯防止**: 読込中(ストリーミング中)は画面が消えないようにしています。
- **サムネイルサイズ切替ボタン**: 実装から漏れていました。上バーのアイコンボタンから100dp/150dpを切替できます。
- **下バーのボタンが反応しない件の修正**: Edge-to-Edge表示によって、システムのナビゲーションバー
  (ジェスチャー領域)にアプリの下バーが重なり、タップがシステム側に取られてしまっていました。
  上バー/下バーにそれぞれ `statusBarsPadding()` / `navigationBarsPadding()` を追加して解消しています。

## 実装済みの内容(初回)

- **フォルダ読み込み**: 起動時にデフォルトで `Documents` フォルダの画像をMediaStore経由で自動読込。
  上バーの「フォルダを開く」からはSAF(`ACTION_OPEN_DOCUMENT_TREE`)で任意フォルダも選択可能。
- **グリッド一覧**: 画面幅に応じた自動列数(`GridCells.Adaptive`)、サムネ100dp/150dpの2段階切替。
- **同画像のみ表示**: 知覚ハッシュ(dHash)でグルーピングし、黄色/山吹色を交互にした外枠のみで
  グループ境界を表現(列をまたいでも判別可能)。単独画像は枠なしで混在表示。
  グループ左上に簡易チェックボックス(タップでグループ一括選択)。
- **閾値スライダー**: デフォルト値の±20%の範囲で調整可能、変更のたびリアルタイム再グループ化。
- **ソート**: 10項目対応、ボトムシートから選択。「同画像のみ表示」ON中はグレーアウトで無効化。
- **画像タップ/長押し**: タップで全画面表示(横スワイプ)、長押しで選択モード開始。
- **選択モード下バー**: 移動(Download/_Moved_固定)・ZIP化・削除・リネーム・全選択解除。
- **リネーム**: `REN`+年月日時分(10桁)+連番。01〜99の後は`AA`〜`ZZ`(676通り)に自動移行。拡張子は維持。
- **スライドショー**: 1/3/5/9秒間隔、タップで次へ、終了時に一覧へ戻り最後に見ていた画像にフォーカス。
- **デザイン**: 藤色(薄紫)+ procedural な和紙風テクスチャ背景。

## 実装時の判断・今後の調整ポイント(要件定義の「軽微な点」に対応)

- **和紙テクスチャ**: フリー素材の実画像ではなく、Canvas上で生成する薄い繊維模様にしています
  (ネットワーク経由での画像取得が今回の環境では行えなかったため)。実際の和紙・藤の花の素材画像を
  用意できれば、`WashiBackground.kt` を画像描画に差し替えるだけで対応できます。
- **`_Moved_`フォルダでの同名ファイル衝突**: 現状はMediaStore標準の重複回避(自動リネーム)に委ねています。
  厳密な衝突チェックが必要であれば `FileOperations.resolveNonCollidingName` を拡張してください。
- **連番が`AA〜ZZ`(676通り)を使い切った場合**: 末尾に追加の数字を付けて衝突回避する簡易フォールバックです。
- **下バーの「拡張」ボタン**: 将来の拡張機能用の予約枠として配置のみ(タップ時の処理は未実装)。
- **通常時の「リネーム」ボタン**: 現状は選択モードでのリネームのみ実装しています。通常時タップ時の挙動
  (例:「まず選択してください」という案内を出す、など)は好みに応じて追加してください。
- **グループ判定の閾値の実際の見え方**: 実機でスライダーを動かしながら、`DEFAULT_THRESHOLD`(現在10)を
  調整してみてください(`ImageGrouping.kt`)。

## 実機フィードバックを受けての修正(3回目)

- **移動/削除/リネームが「0件」になる不具合を修正**: Android 11以降、自分のアプリが作っていない
  MediaStore項目(他アプリが保存した画像など)を変更するには、事前にシステムの同意ダイアログ
  (`MediaStore.createWriteRequest` / `createDeleteRequest`)を経由する必要があり、これを実装していな
  かったのが原因でした。今回、移動・削除・リネームのいずれも、実行前にシステムの確認ダイアログが
  一度表示されるようになります。「許可」を選ぶと処理が実行されます。
- **初期読込フォルダを `Download/未整理` に変更**(移動先の `Download/_Moved_` は変更なし)。
- **一覧右端にスクロール位置バーを追加**: 全体を100%として現在位置を表示し、ドラッグでその位置まで
  ジャンプできます。
- **「同画像のみ表示」に彩度・明度プリセット(A/B/C)を追加**: 判定の厳しさスライダーの右に
  A(厳しめ)/B(標準)/C(緩め)のワンタップボタンを配置。彩度・明度が近い画像同士かどうかも
  グルーピングの判定に加味します(image_sort_selectorでの経験を踏まえた新規実装です。以前のロジックの
  移植ではなく、今回新しく組み込んだものです)。
- **ZIP書庫の中身を閲覧できるように対応**: 上バーに「ZIPを開く」ボタンを追加。選択したZIPは
  アプリのキャッシュ領域に一度展開してから、通常のフォルダと同じように一覧・グルーピング・選択操作が
  行えます(Androidの標準機能だけではZIPの中身に直接アクセスする手段が無いための対応です)。

## 実機フィードバックを受けての修正(4回目)

- **拡大表示中の長押しで一覧に戻る**: 通常フォルダ・ZIP書庫どちらの拡大表示でも、長押しで一覧表示に戻れます(右上の×ボタンも引き続き使えます)。
- **前回開いたフォルダ/ZIPを記憶し、起動時に自動読込**: 次回起動時は前回開いていたものが自動で開きます。
  (アクセス権限が切れていた場合は既定フォルダへ自動フォールバックします)
- **履歴ボタンを追加**: 上バーのフォルダ/ZIPアイコンの右に「履歴」アイコンを追加。過去に開いたフォルダ・
  ZIP書庫の一覧(最大10件)からダイレクトに開き直せます。
- **グループ化が効いているように見えない問題を修正(重要)**: 実は「同画像のみ表示」ON時に、
  同じグループの画像同士を実際には隣接させて並べ替えておらず、元のソート順(日付順など)のまま
  個別に枠を判定していました。そのため同じグループの画像が離れた位置にあると、それぞれ孤立した
  小さな枠になってしまい、設定を変えても見た目にほとんど変化が出ませんでした。今回、各グループの
  メンバーを初出位置にまとめて隣接配置するよう修正しています。
- **設定変更の効果を確認しやすくする表示を追加**: 「判定の厳しさ」スライダー・プリセットA/B/Cの並びに
  「グループ: X件」という現在の検出グループ数を表示するようにしました。設定を変えた際に数字が
  変化するかどうかで、効果を確認しやすくなります。
- **「グループのみ」表示チップを追加**: ONにすると、グループに属さない単独画像を一覧から隠し、
  グループ化された画像だけを表示します。設定の効果を視覚的に確認しやすくするためのものです。
- **スライダーのドラッグ中の負荷対策(デバウンス)**: 判定の厳しさスライダーは、指を離してから
  300ミリ秒後にまとめて再グループ化するようにしました(ドラッグ中に毎フレーム重い処理が走るのを防止)。

## 実機フィードバックを受けての修正(5回目・重要な性能修正)

- **SAFフォルダ読込が数千枚規模で3分以上ハングする不具合を修正(根本原因)**: `loadFromTreeStreaming`が
  `DocumentFile.listFiles()`で取得した各ファイルに対し、`.isFile` / `.type` / `.lastModified()` /
  `.length()` / `.name`を呼ぶたびに個別に`ContentResolver.query()`が発生していました(ファイル1件あたり
  6〜7回のIPC通信)。数千枚のフォルダではこれが致命的な遅延の原因となり、一覧がそもそも埋まらないため
  「グループ: 0件」「プリセットA/B/Cを変えても反応なし」という現象にもつながっていました。
  今回、`DocumentsContract.buildChildDocumentsUriUsingTree()` + 単発の`ContentResolver.query()`で、
  ドキュメントID・ファイル名・サイズ・更新日時・MIMEタイプを一括取得する方式に書き換え、
  クエリ回数をフォルダ1件につき1回に削減しました。

## 実機フィードバックを受けての修正(6回目)

- **「グループ: 0件」のまま進まない不具合を修正(根本原因その2)**: 読み込みバッチが届くたびに
  グループ化(ハッシュ計算)処理を中断して最初からやり直す実装になっていたため、2500枚規模だと
  読み込みが完了するまでグループ化が一度も完了しない状態でした。今回、読み込み中(ストリーミング中)は
  軽量な一覧表示のみ更新し、実際のハッシュ計算・グループ化は**読み込み完了後に1回だけ**実行するように
  変更しました。あわせて`computeHashes`を1枚ずつの直列処理から16枚並列処理に変更し、計算時間そのものも
  短縮しています。
- **ファイルカウンター表示**: 上バーのフォルダ名の下に、読み込み中は「読込中 1200 / 2500 枚」の形で
  読み込み済み数とフォルダ内総数を表示するようにしました。読み込みが進んでいることが一目で分かります
  (SAFフォルダ・MediaStoreフォルダのどちらも、読み込み開始時点で総数が判明する方式になっているため、
  最初のバッチから総数が表示されます)。
- **画面消灯防止(keepScreenOn)の対象を拡大**: 従来は読み込み中(ストリーミング中)のみ画面点灯を
  維持していましたが、読み込み完了後のグループ化(ハッシュ計算)処理中も画面が消えないように拡張しました。
  2500枚規模だとハッシュ計算にも時間がかかるため、その間の消灯を防ぎます。

## 実機フィードバックを受けての修正(7回目)

- **カウンター表示が一瞬しか見えない件**: これは不具合ではなく、SAFフォルダ読込の高速化(5回目の修正)が
  効いて、メタ情報の一括取得自体がほぼ一瞬で終わるようになったためです(「1670/1800」のような
  途中経過が一瞬しか見えないのは、読込がそれだけ速くなった証拠です)。挙動としては正常です。
- **グループ化中の画面ブラックアウトの対策**: `computeHashes`が`Dispatchers.Default`(CPU用、
  コア数と同じ並列数)で動いていたため、大量枚数だと全CPUコアを使い切ろうとしてメインスレッド(UI描画)を
  圧迫し、画面消灯防止の反映が遅れる/カクつく可能性がありました。実際の処理時間の大半は
  「SAF経由でファイルを開くIO待ち」であってCPU計算そのものではないため、`Dispatchers.IO`
  (IO待ちに向いた並列処理)に切り替え、あわせて並列数も24に増やしました。
- **新しいフォルダ読込中に前のフォルダのグループ数が残って見える件を修正**: 読込中(ストリーミング中)は
  「グループ: 読込完了後に計算」、グループ化処理中は「グループ: 計算中…」と表示するようにして、
  古い数字が新しいフォルダの結果であるかのように誤解されないようにしました。
- **プリセットA/B/Cを「同画像のみ表示」から独立させ、単体で機能するように変更**:
  従来はプリセットが「同画像のみ表示」ON時のハッシュ判定の追加条件(彩度・明度の許容差)としてのみ
  機能しており、しかもUI自体がスイッチONの時しか表示されない配置になっていました。
  今回、A/B/Cボタンを常時表示に変更し、上バーの「同画像のみ表示」の左に移動しました。
  「同画像のみ表示」がOFFの状態でプリセットを選ぶと、ハッシュ判定を使わず、彩度・明度のみを基準に
  グルーピングする独立モードとして動作します(前アプリ image_sort_selector のプリセット単体仕分け
  機能に相当)。「同画像のみ表示」がONの時は、従来通りハッシュ判定+プリセットの組み合わせで動作します。
- **履歴からアクセスできなくなったフォルダ/ZIPを自動整理**: 履歴から開こうとした際、実際にはもう
  アクセスできない(移動・削除済みなど)場合は、「「◯◯」が見つからないため、履歴から削除しました」と
  通知した上で、そのエントリを履歴から自動的に削除するようにしました。前回開いていたフォルダ/ZIPを
  起動時に自動で開く処理でも同様にチェックし、アクセスできなければ履歴から削除して既定フォルダへ
  フォールバックします。

## 実機フィードバックを受けての修正(8回目・移動/削除/リネームのクラッシュを修正)

- **カウンター表示について**: 一瞬しか見えないのは不具合ではなく、SAF読込の高速化(5回目)がしっかり
  効いている証拠でした。ただ、瞬間的で分かりにくいとのことなので、フォルダ名の右に読み込み中だけ表示される
  小さなスピナーを追加しました。数字を目で追わなくても、読み込み中かどうかが一目でわかります。
- **移動/削除/リネームでアプリが繰り返し落ちる不具合を修正(根本原因)**: `MediaStore.createWriteRequest`
  / `createDeleteRequest` は MediaStore の URI 専用のAPIで、SAFで選択したフォルダの画像
  (DocumentsContract系のURI)を渡すと `IllegalArgumentException` で即クラッシュしていました。
  これが「移動・削除・リネームを押すと繰り返し停止する」不具合の直接の原因でした。
  今回、開いているフォルダの種類(①既定のDownload/未整理=MediaStore、②SAFで選択したフォルダ、
  ③ZIP書庫を展開したローカルキャッシュ)を判定し、それぞれに適したAPI
  (①MediaStore、②DocumentsContract.moveDocument/deleteDocument/renameDocument、
  ③java.io.Fileの直接操作)を使うように分岐しました。②③の場合は、フォルダ選択時に取得済みの
  アクセス権限だけで操作できるため、システムの同意ダイアログ自体も不要になっています。
- **読込・グループ計算が終わるまで移動/削除/リネームをグレーアウト**: 内部データが確定する前に
  操作されるのを防ぐため、読込中(ストリーミング中)は移動・削除・リネームのボタンを押せないようにし、
  読込完了後に通常表示に戻るようにしました。
- **スライドショー中の画面ブラックアウトを修正**: 画面消灯防止の対象にスライドショー中も含めるようにしました。
  なお、一覧表示のまま何も操作せず放置した際の消灯は、通常のAndroidの画面タイムアウトの挙動であり、
  常時点灯にはしていません(バッテリー消費とのバランスのため、読込・計算・スライドショーなど
  「アプリが能動的に処理・表示している間」だけ点灯を維持する設計です)。
- **スライドショーの開始位置と終了後の一覧追従**: 従来は常に先頭の画像から始まっていましたが、
  今回、①画像を選択中であれば選択の中で表示順が最も早いもの、②選択がなければ一覧表示で
  現在見えている画像、を開始位置にするようにしました。また、スライドショー終了後は、
  終了時点の画像の位置まで一覧表示側が自動でスクロールして追従するようにしました
  (終了後にフルスクリーン表示を開く従来の挙動は廃止し、一覧に戻る形に変更しています)。
