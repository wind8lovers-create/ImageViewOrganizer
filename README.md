# Image View Organizer

これまでのプランニング(要件定義)に基づいた、新規Androidプロジェクトです。
`image_sort_selector` からはロジック(知覚ハッシュ・グルーピング)のみを再実装し、UIはすべて新規に組み直しています。

## 開くには

1. Android Studio(Koala以降推奨)で「Open」→ このフォルダ(`ImageViewOrganizer`)を選択
2. 初回オープン時、Gradle Wrapperのjarが同梱されていないため、Android Studioが
   「Gradle wrapper が見つかりません、再生成しますか」といった案内を出すことがあります。
   その場合はそのまま「OK」で進めてください(distributionUrlは Gradle 8.7 を指定済みです)。
3. Sync後、実機(Android 12以降/Pixel 9など)を接続してRun

## 実機フィードバックを受けての修正(2回目)

- **デフォルト読込フォルダを変更**: `Documents`はAndroidのSAF/プライバシー制限で直接アクセスできない
  端末があるため、`Pictures/未整理` に変更しました。
- **段階読込(ストリーミング)**: 2500枚のような大量フォルダでも、まずタイムスタンプ新しい順に
  50枚ずつ画面へ反映し、残りはバックグラウンドで読み込み続けます。全件揃うまで待つ必要はありません。
- **EXIF読込の遅延化**: 撮影日(EXIF)の読込は、実際に「撮影日でソート」を選んだ時だけ行うようにしました。
  以前は全件の初期読込時にEXIFを読みに行っており、これが大量枚数での遅さの主因の一つでした。
- **画面消灯防止**: 読込中(ストリーミング中)は画面が消えないようにしています。
- **サムネイルサイズ切替ボタン**: 実装から漏れていました。上バーのアイコンボタンから100dp/150dpを切替できます。
- **下バーのボタンが反応しない件の修正**: Edge-to-Edge表示によって、システムのナビゲーションバー
  (ジェスチャー領域)にアプリの下バーが重なり、タップがシステム側に取られてしまっていました。
  上バー/下バーにそれぞれ `statusBarsPadding()` / `navigationBarsPadding()` を追加して解消しています。

## 実装済みの内容(初回)

- **フォルダ読み込み**: 起動時にデフォルトで `Documents` フォルダの画像をMediaStore経由で自動読込。
  上バーの「フォルダを開く」からはSAF(`ACTION_OPEN_DOCUMENT_TREE`)で任意フォルダも選択可能。
- **グリッド一覧**: 画面幅に応じた自動列数(`GridCells.Adaptive`)、サムネ100dp/150dpの2段階切替。
- **同画像のみ表示**: 知覚ハッシュ(dHash)でグルーピングし、黄色/山吹色を交互にした外枠のみで
  グループ境界を表現(列をまたいでも判別可能)。単独画像は枠なしで混在表示。
  グループ左上に簡易チェックボックス(タップでグループ一括選択)。
- **閾値スライダー**: デフォルト値の±20%の範囲で調整可能、変更のたびリアルタイム再グループ化。
- **ソート**: 10項目対応、ボトムシートから選択。「同画像のみ表示」ON中はグレーアウトで無効化。
- **画像タップ/長押し**: タップで全画面表示(横スワイプ)、長押しで選択モード開始。
- **選択モード下バー**: 移動(Download/_Moved_固定)・ZIP化・削除・リネーム・全選択解除。
- **リネーム**: `REN`+年月日時分(10桁)+連番。01〜99の後は`AA`〜`ZZ`(676通り)に自動移行。拡張子は維持。
- **スライドショー**: 1/3/5/9秒間隔、タップで次へ、終了時に一覧へ戻り最後に見ていた画像にフォーカス。
- **デザイン**: 藤色(薄紫)+ procedural な和紙風テクスチャ背景。

## 実装時の判断・今後の調整ポイント(要件定義の「軽微な点」に対応)

- **和紙テクスチャ**: フリー素材の実画像ではなく、Canvas上で生成する薄い繊維模様にしています
  (ネットワーク経由での画像取得が今回の環境では行えなかったため)。実際の和紙・藤の花の素材画像を
  用意できれば、`WashiBackground.kt` を画像描画に差し替えるだけで対応できます。
- **`_Moved_`フォルダでの同名ファイル衝突**: 現状はMediaStore標準の重複回避(自動リネーム)に委ねています。
  厳密な衝突チェックが必要であれば `FileOperations.resolveNonCollidingName` を拡張してください。
- **連番が`AA〜ZZ`(676通り)を使い切った場合**: 末尾に追加の数字を付けて衝突回避する簡易フォールバックです。
- **下バーの「拡張」ボタン**: 将来の拡張機能用の予約枠として配置のみ(タップ時の処理は未実装)。
- **通常時の「リネーム」ボタン**: 現状は選択モードでのリネームのみ実装しています。通常時タップ時の挙動
  (例:「まず選択してください」という案内を出す、など)は好みに応じて追加してください。
- **グループ判定の閾値の実際の見え方**: 実機でスライダーを動かしながら、`DEFAULT_THRESHOLD`(現在10)を
  調整してみてください(`ImageGrouping.kt`)。

```
app/src/main/java/com/hazuki/imageorganizer/
├── MainActivity.kt
├── data/
│   ├── ImageItem.kt          # 画像1件のデータモデル、ソート項目、サムネサイズ
│   └── ImageRepository.kt    # MediaStore/SAFからの画像読込
├── util/
│   ├── PerceptualHash.kt      # dHashによる知覚ハッシュ計算
│   ├── ImageGrouping.kt       # Union-Findによるグルーピング
│   ├── RenameUtil.kt          # REN命名規則
│   └── FileOperations.kt      # 移動・削除・リネーム・ZIP化
├── viewmodel/
│   ├── OrganizerUiState.kt
│   └── ImageOrganizerViewModel.kt
└── ui/
    ├── theme/                 # 藤色パレット・和紙背景
    ├── components/            # TopBar, BottomBar, ImageGrid, SortBottomSheet, FullscreenViewer, SlideshowOverlay
    └── screens/MainScreen.kt  # 画面全体の組み立て
```
